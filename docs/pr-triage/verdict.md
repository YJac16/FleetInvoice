## Two things still open on demo (security)

- **Platform-owner self-grant (#49).** On demo, `profiles_update` (latest is 00055) lets a user update their own row. No later migration adds a trigger or column revoke for `profiles.is_platform_owner`. If Supabase's default table `UPDATE` grant to `authenticated` is still in place, any signed-in user can make themselves a platform owner. In the same PR, `app/api/compliance/scan/route.ts` `loadRetainedDocumentBytes` on demo still reads a document by id with the service client and **no org or subject check** (#49 binds both). `subscriptions_select` on demo is still "any member" (#49 limits it to admins). I did not test any of this against a database. It is from reading the migrations and code.
- **Direct trip-price writes (#73).** Demo has no `trips_reject_direct_billing_price` or equivalent. 00079 only revokes column **SELECT**. Staff with table `UPDATE` can still write `manual_unit_price` / `manual_price_area_key` / `reprice_on_next_sync` directly.
